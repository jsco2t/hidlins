## Implementation and review

- Added `LanTransport`, a blocking `SyncTransport` implementation using only checked `LocalEndpoint` candidates, two-second per-candidate timeouts, eight attempts, a ten-second total budget, actual connected-peer revalidation, fixed IK, strict protocol state, bounded streaming, and stable string-free failures.
- Candidate ordering puts the explicit routing hint first and deterministically deduplicates discovery results. A pinned-key handshake failure is terminal and cannot downgrade to pairing.
- Added cloneable cooperative cancellation checked before connection attempts and every stream boundary.
- Added `sync_vault`, which unlocks the sealed client identity, requires an active pinned authority, drives the established merge truth table, and transactionally persists transport-neutral SHA-256 remote/local versions.
- Renamed reusable orchestration concepts from object/PUT/ETag vocabulary to `SyncVersion`, `SyncSnapshot`, conditional commit, `remote_version`, and `max_commit_attempts`. The generic retry branch now checks `IsPreconditionFailed` before error conversion, so LAN stale versions receive the same merge retry semantics as memory/S3 transports.
- Set the default conditional-commit budget to two total attempts: the initial attempt plus exactly one retry. Explicit test budgets remain supported.
- Added atomic local configure/status helpers for server/client roles and secret-free role/pairing/client-count status.
- Added process-local startup tracking: an attempted first configured unlock consumes the one automatic attempt even on failure; re-unlock and post-save never schedule; manual requests remain repeatable.
- Added pair-and-import that requires active bilateral client trust, validates encrypted KDBX bytes with caller-supplied secure credentials before writing, installs with the core atomic writer, attaches local V1 config, registers transactionally, and removes the newly-created file if registration fails. Invalid input leaves no file or registration.
