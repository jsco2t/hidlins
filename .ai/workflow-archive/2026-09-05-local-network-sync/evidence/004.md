## Implementation and review

- Added generic domain-separated secret sealing with Argon2id and ChaCha20-Poly1305. Derived keys, plaintexts, and identity private keys are zeroizing; serialized envelopes contain only salt, nonce, and authenticated ciphertext; debug and error output is redacted.
- Added per-vault/per-role/per-installation Noise static identities, canonical public identity and installation IDs, secure unlock, and password rewrap that preserves the public identity.
- Added six-character Crockford SAS derivation over the authenticated pairing transcript, a monotonic three-minute pairing window, one-candidate and three-failure bounds, bilateral confirmation, explicit rejection, and zeroization of supplied SAS values.
- Added transcript-bound transaction IDs and a construction boundary that permits durable pairing state only from `ConfirmedPairing`, preventing callers from promoting an unauthenticated raw transcript hash.
- Added V1 local-only config and trust records with exact public-key pinning, roles, provisional state, remote version pointers, revocation, rename, explicit client redesignation, strict parsing, and atomic latest-registry mutation.
- Pairing commits are crash-recoverable at every persistence boundary. The server retains a bounded, non-authorizing activation receipt so an exact authenticated transaction can recover a lost activation acknowledgement; mismatched, expired, replaced, or revoked transactions fail closed.
- Added a typed `AuthorizedTransport` boundary that can be constructed only from a completed, active, exact pinned IK and exposes encrypted transport operations without exposing an authorization bypass.
- Review also repaired private-key stack lifetime during Noise generation, prevented a no-candidate confirmation from consuming the failure budget, and verified two stale registry writers can update different peers without losing either update.
- The persisted schema accepts only `kind = "local"`; S3-shaped transport configuration is rejected. No new dependency was introduced.
- Updated the normative protocol document with exact activation-receipt recovery semantics and expanded the fast security target to include the identity/trust suite.
- `git diff --check` passed and the frozen approved-plan hash remained unchanged.
