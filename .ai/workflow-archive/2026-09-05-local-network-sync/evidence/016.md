## Implementation

- Implemented by: main
- Attempt count: 1
- Added per-peer revocable authorization permits. Every network-originated host operation carries its permit, and execution holds a linearization gate through the host operation so trust replacement cannot return while a removed peer can still reach a commit point.
- Live connections now record whether they are pending, pairing, or authenticated as a specific peer. Trust replacement revokes removed permits and shuts down only sockets owned by removed peers; retained peers continue normally.
- Replaced the independent connection counter with ownership of a fixed socket slot. A guard exists only after a slot is reserved and releases exactly that slot, eliminating the rejected-address decrement underflow.
- Integrated the production runtime with `PairingWindow`: one admitted SAS candidate, three total failures, the fixed three-minute deadline, failure-exhaustion closure, pairing-only advertisement withdrawal, pairing-socket shutdown, and authority-prompt cancellation.
- Split authority cancellation from terminal shutdown so closing one pairing window does not prevent a later explicit window. CLI uses a cancellation generation; TUI and API cancel only their pending prompt.

## Test-forward record

- `trust_replacement_closes_only_removed_live_peers` failed before the repair because the removed peer received another response on its existing socket. It passes after peer-aware socket ownership and permit revocation.
- `revocation_cancels_a_dequeued_commit_before_execution` failed before the repair because the dequeued upload changed the canonical version after revocation. It passes after authorization is carried to the host commit boundary.
- The composite-review reproductions established that production pairing used only an atomic boolean/deadline and that rejected source addresses decremented an unreserved atomic count. Real-loopback regressions now exercise single-candidate admission, active-prompt cancellation, three malformed XX failures, fourth-attempt rejection, connection-cap rejection, and later slot reuse.
