## Implementation

- Implemented by: main
- Attempt count: 1
- Removed automatic scheduling from the Rust `unlock` commit. Flutter now returns the usable local vault first, runs the platform-appropriate trusted discovery pass, sends native candidates through Rust validation, and only then invokes the explicit once-per-process startup trigger.
- Desktop discovery now polls for a bounded 1.2-second window instead of starting a browser and immediately reading an inevitably empty queue.
- Mobile pause/inactive/hidden/detached lifecycle reports immediately cancel in-flight client sync and pairing work while retaining the existing vault-lock grace behavior. The native iOS and Android owners already stop discovery on every non-resumed lifecycle transition and on teardown.
- The mobile simulator scenario now exercises `BridgeSyncRepository` with native discovery after unlock; it no longer injects a literal endpoint into Rust before the startup assertion.
- Added a non-serializable, non-parseable `LocalBindEndpoint` that permits port zero only for a validated bind interface. TUI server mode binds through this type and exposes only the real, nonzero `LocalEndpoint` returned by the kernel.
- Listener shutdown now drops the shared admission socket before joining the accept loop, so toggle-off, lock/drop, and process teardown cannot leave the port connectable.
