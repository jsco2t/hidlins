## Test-forward repair evidence

- The initial configuration check failed with `android.newDsl=true`; the repair
  established `android.builtInKotlin=true`, `android.newDsl=false`, AGP 9.1.0,
  Gradle 9.3.1, and a settings-only Kotlin 2.4.0 `apply false` declaration. The
  checker now passes and rejects seven invalid configurations.
- The first full build failed because a generic dependency report locked
  Flutter's unsupported ARMv7 engine. The lock state was regenerated under the
  exact `android-arm64,android-x64` contract, and the checker now rejects legacy
  ARMv7/x86 engine locks.
- Strict dependency verification then rejected the host-specific macOS AAPT2
  artifact. Actual packaging generated the macOS checksum; the official Google
  Maven Linux artifact was downloaded without execution and SHA-256 pinned, so
  both required CI hosts are covered.
- Emulator logs exposed a missing `GeneratedPluginRegistrant`, and the first
  direct `flutter pub get` repair made release compilation fail by directly
  referencing the debug-only integration-test plugin. The final repository
  normalizer registers that plugin reflectively only when present, keeps it out
  of release, and the APK inspector now requires the registrant class. Both
  debug and test-signed release builds then launched without registrant or fatal
  runtime errors.

minimal application/JNI bootstrap, and Flutter remains presentation. Legacy
Cargokit Gradle execution and the applied Kotlin Android plugin are absent.
First-party Kotlin and Java warnings are fatal; the Gradle lock and verification
files bind the resolved graph without adding a product dependency.

stale verifier metadata after the shared wrapper upgrade. The final review found
