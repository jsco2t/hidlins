## Test-forward warning evidence

Before enforcement, the intentional fixture was compiled with the repository's
existing normal Cargo policy:

`env -u RUSTFLAGS cargo check --manifest-path tools/build-policy/rust-warning-fixture/Cargo.toml --offline --locked`

It incorrectly exited 0 after emitting `unused variable:
warning_only_first_party_code`. After enforcement, `make build-policy-check`
passes only when the same compile exits nonzero specifically on that warning.
The check recursively supplies `-C debuginfo=0` and verifies both that caller
flag and `-D warnings` reach the probe.

## Build-path audit

- Cargo: Make appends/exports `-D warnings` at file scope, so workspace builds,
  release, run, check, tests, feature gates, bridge smoke build, interop drivers,
  benchmarks, completions, docs, and Cargo calls inside Make-owned helper scripts
  inherit it. `RUSTDOCFLAGS` is appended/exported for rustdoc as well. The prior
  one-off `RUSTFLAGS` overwrite was removed.
- Native Rust bridge: desktop Cargokit inherits exported `RUSTFLAGS`. Android
  Cargokit previously replaced it with `CARGO_ENCODED_RUSTFLAGS` for its NDK
  linker workaround; the inventoried local patch now preserves/encodes inherited
  `RUSTFLAGS` before adding its linker flag.
- Flutter/Dart: both current artifact targets (`app-build-linux` and
  `app-build-macos`) require `app-analyze`, which explicitly makes warnings and
  infos fatal. Flutter build/test/run also inherit the exported Rust policy.
- Linux: `-Werror` is attached only to `${BINARY_NAME}`. The shared
  `APPLY_STANDARD_SETTINGS` retains `-Wall` but no longer makes vendored plugin
  warnings fatal.
- Apple: macOS `AppInfo.xcconfig` and iOS Runner Debug/Release (also used by
  Profile) enable C-family and Swift warnings-as-errors on Runner targets; Pods
  and Swift packages keep their own settings.
- Android: only the application module enables Kotlin
  `allWarningsAsErrors` and Java `-Xlint:all -Werror`; plugin modules keep their
  own policies.
- Make contains no direct CMake, Gradle, or Xcode compilation recipe beyond the
  audited Flutter artifact entry points.
