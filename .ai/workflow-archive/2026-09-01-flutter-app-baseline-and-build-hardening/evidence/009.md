## Test-forward evidence

1. The iOS native/security tests were introduced before the Swift mechanisms and initially failed to compile/link; after the minimum platform implementation they passed on the simulator.
2. Existing router/material shell tests exposed that the new first-run vault selection required registered-vault fixtures. They failed with the first-run page and an unoverridden session provider, then passed after the shared test helper registered a vault and supplied the normal repository overrides.
3. Main-thread review identified a fail-open lifecycle race: the native shield could be removed after Rust merely stored `resumed`, before the one-second ticker reconciled the lock. `lifecycle_detached_locks_immediately` was strengthened first and failed because the vault remained open after the report returned. Shared ticker progress plus synchronous Rust reconciliation made that regression green.
4. Regenerating the bridge initially exposed the new internal ticker state as an FFI type and broke both iOS target checks. Marking that Rust-only type ignored at the boundary removed the accidental expansion; regenerated bindings, iOS checks, and the exact API-generation gate then passed.

## Main-thread review

The review preserved the approved boundary: Rust owns lifecycle timers, lock decisions, secret transfer lifetime, vault mutation, and sync policy; Dart coordinates typed state and presentation; Swift owns only iOS lifecycle, storage, picker, pasteboard, and snapshot mechanisms. CocoaPods/Cargokit remains explicit because the real Rust bridge is pod-based, and no dependency was added.

Two high-confidence findings were repaired before acceptance:

1. Router and Material compatibility fixtures did not model the newly required registered-vault state, so the full Flutter suite failed despite focused platform tests. A shared registration helper repaired the fixtures without weakening production behavior.
2. The original lifecycle acknowledgement meant only “Dart forwarded the report,” not “Rust has decided and the UI reflects that decision.” Lifecycle reconciliation now occurs before the Rust call returns, the result crosses the generated boundary, Dart waits for the matching rendered provider state, and native code rejects acknowledgements missing that authoritative state. The failure mode is intentionally an opaque shield that stays visible.
