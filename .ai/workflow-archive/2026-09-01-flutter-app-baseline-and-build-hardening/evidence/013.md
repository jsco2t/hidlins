## Test-forward repair evidence

- The first real Android bridge lifecycle run failed because Rust 1.95's
  standard file-lock implementation reports `Unsupported` on Android. Existing
  host contention tests plus the failing device lifecycle test pinned the
  contract before the Android-only Bionic `flock` adapter was added. Host
  same-process/cross-process contention, process-death release, and both API 29
  and API 36 real-bridge runs then passed.
- The complete Flutter suite exposed a search-to-entry keyboard-copy regression:
  the nested `/entries` parent route cleared the child route's UUID. The focused
  router test failed with a null copy UUID before the repair and passed after
  null parent routes stopped overwriting the shared selection.
- The new touch-visible copy control made an old hover test fail because Flutter
  widget tests default to an Android platform. The test harness now names the
  platform explicitly and proves both contracts: hidden-until-hover on macOS and
  always reachable on Android.
- The emulator harness self-tests pin rejection of incomplete matrices, command
  timeout, secret redaction, failed Flutter device runs, and malformed result
  metadata. API and ABI assertions prevented a connected emulator from being
  misrepresented as another matrix member.

## Main-thread architecture review

Shared Dart UI remains the presentation layer and Android code remains an OS
mechanism adapter. KDBX, secret ownership, locking policy, sync, and conflict
resolution stay in Rust. The only platform-specific core branch is a narrow,
documented Android advisory-lock syscall because the Rust standard library does
not expose its file-lock implementation on Android; it is covered by the same
locking invariants as other hosts. Emulator orchestration is outside product
code, reads a declarative matrix, redacts logs before recording hashes, and has
bounded process-group timeouts. No unresolved high-confidence Task 013
architecture finding remains.
