## Test-forward repair evidence

- The first Android instrumentation compile failed because the lifecycle,
  clipboard, storage, keyfile, and snapshot-cover production types did not
  exist. Implementing those mechanisms made the device suite compile and pass.
- Runtime clipboard testing then failed on Android 13 because the test attempted
  clipboard access before the activity had window focus. The harness was
  repaired to wait for a focused foreground activity, after which replacement
  preservation and owned clearing passed.
- Expanding native lifecycle handling exposed a pending two-second lifecycle
  acknowledgement timer after Flutter widget teardown. A focused router test
  reproduced it; racing the rendered-state wait against widget disposal made
  the focused and full Flutter suites pass without weakening fail-closed cover
  behavior.
- Main-thread review identified an outstanding picker result abandoned during
  activity destruction. The new regression initially failed to compile because
  no bounded pending-result lifecycle existed. `beginPicker` plus deterministic
  completion on cancellation, launch failure, and activity destruction repaired
  the race; keyfile URI references now use a durable `SharedPreferences.commit`
  before success is returned.
- The first attempted API 29 run was correctly rejected after an API assertion
  was added: a stale API 33 emulator was connected. After stopping it, the
  dedicated `hidlins-api29` image passed and the harness now refuses to
  misrepresent a connected runtime's API.
- A test-only content provider now throws a real resolver `SecurityException`;
  both API 29 and API 33 report the typed denied result instead of relying only
  on a Dart fake.

## Main-thread architecture review

The final dependency direction is Rust policy and secret ownership → a narrow
JNI/platform-channel boundary → Android OS mechanisms. Java/Kotlin does not
parse vaults, decide lifecycle lock policy, merge data, or expose clipboard
plaintext to Dart. Storage paths are app-private, SAF references are non-secret,
and backup exclusion is explicit. Picker state is deliberately local to the
activity but now terminates with a bounded typed failure on destruction rather
than leaking a stale Flutter callback. No unresolved high-confidence
architecture finding remains in Task 012 scope.
