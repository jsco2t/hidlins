## Main-thread review

The transaction stages a KDBX encrypted with the new credential and a complete sealed registry output as fixed sibling files. A mode-0600 marker records only the validated vault name, registry key, phase, and SHA-256 hashes. The live operation and restart recovery both use the stable vault-then-registry advisory-lock order. Each rename is followed by a containing-directory fsync. Recovery accepts only internally derived paths and hash-matching old/new states; when unrelated registry data changed after a crash, it merges only the staged `sync` value into the latest registry rather than replacing unrelated records.

Pre-marker crashes are distinguishable because no live authority has changed; recovery removes the fixed orphan stages and keeps the old pair. Once the marker is durable, recovery deterministically rolls forward. The marker is removed last, so interruption during cleanup remains recoverable. Ordinary failures after a marker exists lock the session and leave restart recovery in control rather than attempting an unsafe password-dependent rollback.
